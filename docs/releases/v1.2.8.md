# SkillSync v1.2.8 — Manual GitHub tracking for portable skills

Released: 20 September 2026

## Added

- A skill that is a normal directory or a symlink, rather than a local Git checkout, can now be linked to a GitHub repository directly from its details panel.
- The field accepts repository roots in HTTPS or SSH form, for example `https://github.com/PrefectHQ/fastmcp` and `git@github.com:PrefectHQ/fastmcp.git`. SkillSync stores one canonical HTTPS address.

## Fixed

- Saving a repository or a tracked branch refreshes the selected resource immediately. The GitHub check control appears without closing the panel and SkillSync performs the first upstream check automatically.
- A non-Git installation with a manual branch no longer tries to execute local Git branch commands. It falls back to safe GitHub release/tag checking.
- Repository validation rejects non-GitHub hosts, `tree/…` paths, files, queries and fragments so an invalid source cannot be recorded accidentally.

## Example

For `/Users/tomaszboloz/.claude/skills/fastmcp`, enter:

```text
https://github.com/PrefectHQ/fastmcp
```

Click **Save**. SkillSync reveals **Check GitHub** and immediately requests the upstream release or tag. Set `main` in **Tracked branch** only when the local resource is a Git checkout; tags remain the default tracking source for tagged repositories.

## Verification

- Rust configuration compatibility, strict GitHub URL normalisation and scanner routing are covered by automated tests.
- Frontend state coverage verifies that saving the repository refreshes the currently open item and triggers the first GitHub check.

## Breaking changes

None. This is a backward-compatible patch release under Semantic Versioning.
